# Why we built CSOAI's corrections ledger on machine derivation, not human editing

The corrections feed at `councilof.ai/feeds/corrections.xml` is derived from the same code that produces measurements. **No human edits the feed manually.** That's the operational proof of honesty.

## The temptation

When you have a corrections feed, the temptation is:

1. Find an error
2. Fix the underlying code
3. Update the website with a note
4. Manually add an entry to the corrections feed

This is what most organizations do. It's also what makes corrections feeds useless:

- The feed entry is separate from the measurement
- A reader has to trust that the feed was actually updated
- A reader has to trust that all errors were caught and reported
- A reader has to trust that the feed wasn't edited retroactively

CSOAI rejects this approach entirely.

## What machine derivation means

CSOAI's corrections feed is generated by the same pipeline that produces measurements:

1. Every measurement run produces a signed card
2. Cards are versioned
3. When an error is found, the underlying measurement is re-run with a new version
4. The corrections feed entry is automatically generated when the new card supersedes the old
5. The entry states: old card ID, new card ID, reason for correction, timestamp

There is **no human editing of the corrections feed**. The only way to add an entry is to fix the underlying measurement and re-run it.

This means:

- A reader can verify the corrections feed entry against the cards in the root tree
- A reader can verify each "corrected" card by reproducing the conditions
- The corrections feed cannot lie about what was fixed — it's mechanically derived from what was fixed

## The operational proof

When a third party wants to verify CSOAI's corrections:

1. Fetch the corrections feed
2. For each entry, find the old and new cards in the public root tree
3. Verify the new card has higher version than the old
4. Verify the new card supersedes the old
5. Verify the new card has valid Ed25519 signature
6. Verify the new card is in the root tree

If all six checks pass, the correction is real. If any fails, the correction is fake. **No human judgment needed.**

## Why this matters

Human-edited feeds can be censored. They can be quietly removed. They can be backfilled.

Machine-derived feeds are **mechanically honest**. They cannot be censored without changing the underlying measurements. They cannot be backfilled without faking the measurements. They cannot be quietly removed without breaking the measurement history.

## The implementation

The corrections feed is generated by a simple script that:

1. Reads the public root tree
2. Reads the cards in the tree
3. Finds pairs where one card supersedes another
4. Generates an RSS entry for each supersession

There is no separate "corrections database" to compromise. The feed is derived from the cards themselves.

## The bottom line

CSOAI's corrections ledger is honest because it's machine-derived, not human-edited.
